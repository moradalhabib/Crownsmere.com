# Crownsmere property portfolio — implementation and operating guide
_Last updated 4 November 2026. Development branch only; not released._

## Purpose
Crownsmere is an owner-authorised, commission-based introduction service. The public website
displays a curated portfolio of sale and rental homes. **Every enquiry goes to Alaa Qadir at
alaa.qadir@crownsmere.com, copying hello@crownsmere.com.** Alaa qualifies the enquiry,
obtains the client's agreement to share their information, and allocates the client to the
appropriate partner agent. The partner handles viewings, negotiations and the legal
completion/lettings process as agreed.

The website is not a regulated agency substitute or a public CRM. Regulatory onboarding,
commission agreements, privacy notices, terms, particulars and any advertising requirements
must be reviewed before launching listings or inviting active business. The development branch
is deliberately not merged into the live site.

## What was added
- \`properties.html\`: filterable public catalogue for For Sale, To Rent, area and bedrooms.
- \`property-<slug>.html\`: generated single-property page with pictures, public facts, price,
  disclosure, and a named-property enquiry to Alaa.
- \`assets/property.css\`, \`assets/property.js\`: responsive layouts, filtering and email drafting.
  Existing CSS, CSP, no-cookie policy and mail-client-first contact workflow preserved.
- \`tools/property_pages.py\`: one source of truth for safe static listing generation.
- \`data/properties.json\`: empty by default, published properties only after explicit approval.
- Navigation on every page generated by \`tools/build.py\`: Properties integrated in header,
  five-tab mobile bar and footer. Home hero and tiles offer a direct route to Properties.

## Data handling — CRITICAL
**The repository is public. Never commit owners' personal information, private agent deals,
commission agreements, buyer leads, identity documents, exact owner contact details, or
confidential negotiations to this repository, even under \`data/\`.** Jekyll excludes \`data/\`
from the published website, but GitHub itself still exposes version-controlled data. Store
sensitive operating documents and enquiries only in an appropriately secured system.

\`data/properties.example.json\` is an illustrative *unpublished* format only. It contains
invented data clearly labelled as an example and is never ingested by the generator.

Add a real listing to \`data/properties.json\` as an object with:
- \`slug\`: unique lowercase hyphenated URL path
- \`reference\`: unique Crownsmere property reference
- \`status\`: \`draft\`, \`review\`, \`published\`, or \`withdrawn\` (only \`published\` renders)
- \`owner_authority\`: \`true\` only after written marketing authority verified
- \`compliance_cleared\`: \`true\` only after legal/compliance launch review complete
- \`listing_type\`: \`sale\` or \`rent\`
- \`title\`, \`area\`, \`address_public\` (non-sensitive), \`price\` in whole pounds
- \`rent_period\`: \`pcm\` or \`pw\` when renting (default \`pcm\`)
- \`property_type\`, \`bedrooms\`, \`bathrooms\`, \`floor_area_sqft\`, \`description\`
- Optional \`features\`, \`tenure\`, \`council_tax_band\`, \`epc_rating\`,
  \`furnished\`, \`availability\`, \`floorplan\`
- \`photos\`: real, authorised image filenames under
  \`assets/img/properties/<slug>/\`; only \`.jpg\`, \`.jpeg\`, \`.png\`, \`.webp\`, \`.avif\`

Published listings **must** have positive numeric price, basic particulars, permission and
launch-approval flags, and at least one image file. The generator aborts the build if a
listing is marked published without approvals or required fields, so incomplete content
cannot be accidentally published. Drafts/review/withdrawn properties are never output
as HTML, in a sitemap, or in the filter cards.

To build locally:
\`\`\`sh
python3 -m py_compile tools/build.py tools/property_pages.py
python3 tools/test_properties.py
python3 tools/build.py
\`\`\`

## Enquiry and partner allocation
- The property reference is embedded in the email subject and body for lead attribution.
- Visitor contact data is prepared locally in a mail app; no website database receives leads.
- A checkbox confirms Crownsmere may contact the visitor about the property.
- The email explicitly does **not** grant permission for onward transfer to partner agents.
  Alaa obtains separate agreement before allocating the lead.
- A user can reopen the drafted email or copy the text if mailto doesn't launch.
- Alaa's downstream assignment, commission tracking and agency agreements are currently
  manual. A protected CRM/admin portal is a later phase, not a part of this static site.

## Mobbin design reference library (research, not copied assets)
For each substantial UI change, search current Mobbin web screens, flows and website sections
for the relevant pattern **before** implementation. Analyse a small set of patterns, choose
the one fitting the user's task, and then execute a Crownsmere-original implementation.
Never copy competitor branding, text, photographs, code or entire page compositions.

| Site area | Pattern to study on Mobbin | Crownsmere application |
|---|---|---|
| Property search / listing cards | [Zillow property search screen](https://mobbin.com/screens/537c0739-2c80-4c90-88a1-8c68baed0763) | Clear search refinements, immediately visible prices, image-led cards |
| Property detail | [Zillow detail screen](https://mobbin.com/screens/d5f8bb0a-fa13-4584-8ab1-b690aea56262) | Photo gallery, legible facts, persistent enquiry destination |
| Home hero/editorial direction | [KOBU section](https://mobbin.com/sites/sections/d07ad815-77af-4cab-a6ff-c35761c7b2a6) | Restrained hospitality-inspired typography and white space |
| Curated property discovery | [KOBU featured section](https://mobbin.com/sites/sections/4226456d-e845-483a-ad1b-305a93fe7d36) | Sophisticated collection presentation rather than crowded grid |
| About Alaa | [Complex Law team section](https://mobbin.com/sites/sections/b9d2ed7b-7d15-44a1-9e43-d9b19245bfea) | Personal trust, clearly named consultant and transparent service |
| Contact | [Framer contact section](https://mobbin.com/sites/sections/914df681-c24d-4800-bd11-9c144d0175fb) | Simplified mobile-first contact hierarchy |
| Services | [YLLW section](https://mobbin.com/sites/sections/c838e6c7-2e50-40c5-8b29-f61445fd5bc0) | Scannable service-entry cards |
| Footer | [Fiasco section](https://mobbin.com/sites/sections/af0c1930-9ed3-4ed4-9af0-dfbc96b3a625) | Consistent navigation and brand sign-off |

Keep Crownsmere's established warm cream, navy, muted gold, Cinzel wordmark, Inter reading
type, Cormorant Garamond editorial headlines. Prioritise keyboard accessibility, mobile
navigation, correct page metadata and fast self-hosted images. Avoid unnecessary animation,
third-party embeds, tracking, false scarcity badges, decorative 3D or invented stock listings.

## Before release
1. Verify Crownsmere's agency regulatory position, scheme memberships, AML and the partner
   arrangement with qualified counsel or the appropriate regulator.
2. Confirm written owner marketing authority, copyright licences, accurate approved
   particulars, EPC and other material information for each property.
3. Review any applicable disclosure of agency status, material facts and referral fees.
4. Test the mailto handoff to Alaa and the copy recipient from a real browser and device.
5. Get approval to share buyer/tenant details with the allocated agent *per introduction*.
6. Review accessibility, runtime errors, mobile and desktop layouts, generated page/sitemap
   correctness, links, CSP and the no-publication gate.
7. Merge the PR and deploy only when authorised to launch. No automatic merge.
